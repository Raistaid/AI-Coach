# Aimo — Твой тренер в прямом эфире

Человек ставит телефон, запускает вертикальную трансляцию как в Instagram Live, и ИИ-тренер в реальном времени пишет в ленту, что делать сейчас и как получается. Флагманский сценарий — новичок учится чеканить мяч. Зрение и языковая модель работают на устройстве: без сервера приложения, регистрации и API-ключей, видео никуда не уходит. Голосовые вопросы распознаёт браузер и может обрабатывать через свой сервис. Интерфейс на русском.

## Попробовать

Приложение: https://nomad-dreamteam.github.io/Aimo/ (GitHub Pages, деплой из `main` автоматически).

1. Открой ссылку в Safari или Chrome на телефоне. Введи имя и выбери цвет аватара: профиль хранится на устройстве, без пароля и сервера.
2. Главный экран — чат с тренером. Напиши цель своими словами («хочу чеканить, но мяч падает») или нажми навык в кружках сверху. Тренер соберёт маршрут и предложит начать эфир.
3. Эфир открывается во весь экран с фронтальной камерой, чтобы видеть подсказки, стоя перед телефоном: вертикальное видео, шаг урока, лента комментариев тренера, кнопки паузы, камеры, голоса, разметки и крупного режима. Камера включается только после нажатия.
4. После эфира итог появляется в чате и в разделе «Прогресс». Видео не записывается.
5. История чатов открывается свайпом от левого края или кнопкой меню. Каждый новый вход в приложение открывает новый чат.

«Демо без камеры» запускает явно обозначенную симуляцию на нарисованном спортсмене, она не попадает в историю. «Открыть видео» анализирует локальный видеофайл по-настоящему.

## Как работает ИИ

Три уровня, все на устройстве:

1. **Зрение.** MediaPipe Pose Landmarker Lite распознаёт позу; MediaPipe Object Detector (EfficientDet-Lite0, класс «sports ball») находит мяч. Касание — разворот траектории мяча вниз-вверх рядом со стопой; падение — мяч лежит на уровне стоп после серии.
2. **Правила и банк фраз.** Ситуация определяется правилами по углам суставов, видимости и фазам движения. Фраза берётся из банка под выбранный характер, в неё подставляются реальные числа. Работает офлайн на любом телефоне и отвечает мгновенно. Это основа эфира.
3. **Живой тренер (бета).** Маленькая языковая модель в браузере через WebLLM 0.2.86: Qwen2.5-1.5B-Instruct (около 1 ГБ) или Qwen2.5-0.5B для слабых устройств. Включается в настройках, требует WebGPU, работает в Web Worker. Раз в 12 секунд получает только числовую сводку (шаг урока, счётчики, главная ошибка, видимость) и пишет одну живую фразу, а после эфира — итог. Ответ проверяется кодом: русский язык, длина, все числа есть в сводке. Не прошёл проверку — используется фраза из банка.

Характер тренера меняет формулировки и голос, но не факты и не правила безопасности.

## Чат подбора навыков

Над каталогом есть чат «Не знаешь, с чего начать?». Человек описывает цель своими словами, тренер собирает маршрут из навыков каталога: например, «хочу чеканить, но мяч падает» даёт «Баланс на одной ноге → Чеканка мяча». С включённым «Живым тренером» отвечает локальная модель, которой передаётся только описание каталога; код проверяет, что в маршруте только существующие навыки, ответ на русском и без выдуманных чисел. Без модели работает подбор по ключевым словам. Для цели вне каталога тренер честно говорит, что такого навыка пока нет: новые навыки появляются только как проверенные модули в `skills/`, а не из генерации текста. Маршрут сохраняется локально, после прохождения навыка выбирается следующий.

## Честность показателей

- Касания мяча показываются только когда детектор реально видел мяч. Иначе метрика называется «Подъёмы стопы» с пояснением.
- LLM не видит кадров и не может назвать число, которого нет в сводке.
- Нет фиктивных зрителей, лайков, точности и сгенерированных отзывов.
- Пропущенный шаг урока отмечается как невыполненный, а не как пройденный.

## Что реализовано

- Каталог навыков: каждый навык — один модуль данных в `skills/` (уроки, условия перехода, правила, банк фраз, метрики, нужен ли мяч).
- Чеканка: 6 шагов (стойка 3 с → 6 подъёмов без мяча → 3 одиночных касания → серии 3 → 5 → 10). Приседания: 3 шага. Баланс: 3 шага.
- Локальный профиль: имя и цвет аватара на устройстве, вход без пароля и сервера.
- Чат с тренером как главный экран: маршрут из навыков, карточки навыка и итога, история чатов в панели по свайпу слева, новый чат при каждом входе.
- Экран эфира во весь экран: вертикальное видео, LIVE, таймер, шаг урока с прогрессом, лента комментариев, скелет и рамка мяча, реакции на реальные события, рейл кнопок: пауза, камера, голос, разметка, крупно, пропуск шага.
- Светлая и тёмная тема в цветах Facebook: синий акцент, мягкий серый фон, скруглённые карточки; нижние вкладки с подписями: чат, навыки, эфир, прогресс, профиль.
- Камера показывает весь кадр, который анализирует модель; можно переключить на весь экран, на задней камере есть широкий угол 0.5×. Нажатие на таймер показывает кадры анализа в секунду.
- После эфира — карта ритма по засчитанным касаниям, подъёмам или повторам.
- После первого захода приложение и модели зрения работают без интернета.
- Тренер поддерживает обычный разговор: на «как дела» после эфира отвечает про этот эфир с реальными цифрами, на «болит» советует остановиться и при необходимости обратиться к врачу, «нет такого навыка» говорит только на настоящую цель вне каталога.
- Режим «на расстоянии»: когда человек далеко от камеры, последняя фраза и шаг урока показываются во весь кадр; звуковые сигналы и цветная рамка на касание, шаг и ошибку; голос с приоритетом предупреждений.
- Итог эфира и локальная история последних восьми тренировок.
- Освобождение камеры, анимаций, моделей зрения и LLM при остановке и уходе со страницы.

## Локальный запуск

Приложение статическое, сборки не требует. Нужен Python 3 для раздачи файлов:

```sh
cd AI-Coach   # папка репозитория
python3 -m http.server 4173 --bind 127.0.0.1
```

Открой http://127.0.0.1:4173. Камера на телефоне требует HTTPS, поэтому для телефона используй ссылку GitHub Pages. Модели MediaPipe и библиотека WebLLM загружаются с CDN при первом запуске и кешируются браузером.

## Тесты и сборка

Node.js 22 нужен только для тестов и сборки, npm-зависимостей нет:

```sh
node --test              # все тесты: правила, данные, вопросы, речь, кеш моделей, разговор, ритм, клавиатура
node scripts/build.mjs   # собирает dist/ для GitHub Pages (то же делает workflow)
```

Тесты покрывают геометрию, отсутствие человека, частичную видимость, дрожание точек, подъёмы и приседания, трекер мяча (касание у стопы, подброс у рук не считается, падение, шум детектора), переходы по шагам урока, пропуск шага, банк фраз (не меньше 5 вариантов на ситуацию и характер), сводку для LLM и отклонение ответов с выдуманными числами, процентами, английским текстом, эмодзи и лишней длиной. Это тесты на синтетических данных; качество распознавания реального человека проверяется на телефонах по docs/TEST_PLAN.md.

## Ограничения

- MediaPipe даёт ориентиры тела и рамку мяча, а не экспертную оценку техники. Нужны свет, устойчивая камера и всё тело в кадре.
- Детектор мяча может терять мяч при плохом свете или сливающемся фоне; тогда касания не считаются, о чём приложение сообщает.
- Живой тренер требует WebGPU (Chrome, Edge, Safari 26 и новее) и свободную память GPU; без WebGPU работают уровни 1–2.
- Частота анализа зависит от устройства; детектор предметов и мяча автоматически уступает приоритет позе.
- Дополнительные голоса Piper требуют скачивания и локального хранилища. При ошибке используется русский голос браузера; текст остаётся основным каналом.
- Это приватный экран тренировки: трансляции другим зрителям нет.

## Структура и команда

```
index.html, styles.css      интерфейс: вход, чат, навыки, прогресс, профиль, эфир
app/main.js                 загрузчик: профиль, вкладки, панель чатов со свайпом, лист навыка, настройки
app/chat.js                 чат с тренером: сообщения, маршрут, карточки навыка и итога
app/live.js                 эфир: камера, цикл анализа, лента, крупный режим, звук, итог
app/store.js                данные на устройстве: профиль, настройки, чаты, история (чистые функции)
app/ui.js                   мелкие DOM-помощники, шина событий, нижние листы
app/viewport.js             приложение по размеру видимой области, определение клавиатуры
coach-engine.js             зрение: поза, мяч, уроки, правила (MediaPipe)
coach-llm.js, llm-worker.js живой тренер: WebLLM в Web Worker, проверка ответов
coach-planner.js            подбор навыков по цели: ключевые слова и проверка ответа модели
coach-talk.js               разговор в чате: «как дела», спасибо, усталость, боль, итоги; числа только из истории
rhythm.js                   карта ритма: засчитанные движения во времени и ровность интервалов
sw.js                       работа без сети: приложение и модели зрения из кеша
skills/                     каталог навыков, один файл на навык
*.test.mjs                  тесты чистой логики: node --test
scripts/build.mjs           сборка dist/; .github/workflows/pages.yml деплоит её на GitHub Pages
docs/                       промпт проекта, план приёмки, журнал стратегии, запасное видео
```

Два человека ведут агентов и принимают решения; роли агентов и владение файлами описаны в `AGENTS.md`. Для агентов Claude Code в репозитории есть `.mcp.json` с MCP-сервером Context7: документация MediaPipe и WebLLM запрашивается через него.

Документация API: [MediaPipe Pose Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/pose_landmarker/web_js), [MediaPipe Object Detector](https://ai.google.dev/edge/mediapipe/solutions/vision/object_detector/web_js), [WebLLM](https://github.com/mlc-ai/web-llm).

## Сравнение прогресса и развитие

В итогах, чате и истории сравниваются результаты одного навыка, метрики и источника. Для чеканки — лучшая серия, без мяча — подъёмы, для приседаний — повторы, для баланса — лучшее удержание. Камера и видео учитываются отдельно; демо и старые записи без источника не участвуют. Лучший результат ограничен последними 50 сохранёнными записями; количество движений не оценивает качество техники.

`coach-progress.js` и `progress.test.mjs` содержат чистую логику и тесты. Анализ и план функций — в `docs/FEATURE_ROADMAP.md`, роль агента — `.codex/agents/feature_developer.toml`.

## Голос, вопросы и скачивание моделей

В профиле → «Выбрать голос» доступны два самостоятельных голоса Piper:
**Денис** (ровный мужской) и **Дмитрий** (мягкий мужской), а также русские
голоса браузера/системы. Выбери голос, нажми «Скачать голос · 63 МБ», затем
«Прослушать голос». После проверки сохранённых файлов кнопка скачивания
становится тусклой. Есть прогресс и отмена. Выбор сохраняется локально.

Piper озвучивает текст на устройстве в отдельном однопоточном CPU/WASM worker,
без WebGPU, ключей и передачи текста сервису TTS. Веса каждого голоса занимают
около 63 МБ в хранилище этого сайта; при первом озвучивании дополнительно
скачиваются общие модули синтеза с CDN. При смене адреса сайта голоса потребуется
скачать заново. Нужны OPFS и Web Audio (современный Chrome/Safari); на телефонах
скорость надо проверить. При недоступности/задержке синтеза включается русский
голос браузера. Системные голоса зависят от устройства; варианты «онлайн» могут
использовать сервис браузера. Характер тренера меняет формулировки и темп;
высота меняется только у системных голосов. Лицензии: [THIRD_PARTY](docs/THIRD_PARTY.md).

В эфире кнопка «Спросить» открывает поле вопроса и отдельную кнопку микрофона.
Распознанный вопрос отправляется тренеру автоматически; можно написать его
вручную. Счётчики берутся из текущей тренировки, общую подсказку может
сформулировать включённая локальная LLM с проверкой ответа. Демо явно помечено
симуляцией. При недоступном/запрещённом микрофоне остаётся текстовый ввод.
Браузер может передавать аудио своему сервису распознавания; пользователь
разрешил этот режим. Приложение аудиозапись не хранит.

В разделе «Локальные модели» у каждой Qwen есть своя кнопка «Скачать», прогресс
и отмена. После подтверждения кеша кнопка «Скачана» тусклая и недоступна.
Скачанная модель используется автоматически в эфире и чате; запуск происходит
только после подтверждённого кеша. Очистка кеша браузером возвращает возможность
скачивания. Для загрузки через WebLLM нужен WebGPU; это не установка на все
браузеры устройства. Загрузка весов не означает готовность всего приложения
без сети: CDN и поддержка браузера проверяются отдельно.

«Детектор предметов» отмечает поддерживаемые COCO-классы: людей, мяч, бутылки,
стулья и другие. Рамки предметов работают отдельно от разметки позы. Только
распознанный `sports ball` участвует в подсчёте касаний; остальные предметы не
считаются мячом. При сбое детектора анализ позы продолжает работать.
