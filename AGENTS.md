# Aimo — инструкции для команды агентов

## Цель
Нейро-тренер в формате прямого эфира для хакатона. Человек ставит телефон, запускает вертикальную трансляцию как в Instagram Live, и ИИ-тренер в реальном времени пишет в ленту, что делать сейчас и как получается. Флагманский сценарий — новичок учится чеканить мяч. Интерфейс на русском. Полный промпт проекта: docs/PROMPT.md.

Критерии жюри и веса: оригинальность 25%, польза 20%, работоспособность 20%, качество исполнения 15%, работа в команде 10%, использование ИИ 10%. Каждую задачу привязывать к критерию; приоритет по весу.

## Архитектура
- Buildless HTML/CSS/ES modules, статический хостинг GitHub Pages (workflow собирает `dist/` из `main`). Без сервера и платежей; «вход» — локальный профиль на устройстве.
- Главный экран — чат с тренером; эфир открывается из чата, листа навыка или вкладки «+». Модули интерфейса лежат в `app/`, логика ИИ в корне и `skills/`.
- Зрение, правила и языковая модель работают на устройстве, API-ключи не нужны:
  - Уровень 1, зрение: MediaPipe Pose Landmarker (поза) и MediaPipe Object Detector (предметы COCO). В трекер касаний и падений передаётся только класс «sports ball».
  - Уровень 2, проверка движений: `coach-motion.js` считает признаки тела, калибровку под человека, повторы с гистерезисом, удержания и подтверждение ошибок; каждый навык проверяет своё движение в `measure`. Фраза берётся из банка под характер тренера с подстановкой реальных чисел; когда говорить, решает бюджет сообщений `coach-policy.js`. Это основа эфира, работает офлайн.
  - Уровень 3, локальная LLM: WebLLM 0.2.86, модель Qwen2.5-1.5B-Instruct-q4f16_1-MLC (запасная 0.5B). Включается пользователем, требует WebGPU, получает только числовую сводку, пишет живую фразу раз в 10–15 с и итог. Ответ проверяется кодом, при сбое — фраза из банка.
- Каталог навыков: 8 навыков в трёх разделах (футбол, сила, кардио), каждый — отдельный модуль в `skills/`: `view` (ракурс и видимость), `measure` (повторы, попытки, удержания, ошибки), уроки, ошибки с советами, банк фраз, метрика, `demo` для симуляции и тестов. Уроки переключаются только по реальным наблюдениям. Новый навык — один файл и одна строка в `skills/index.js`.
- Дополнительные голоса Piper Denis/Dmitri: явное скачивание в OPFS, локальный однопоточный WASM worker (`app/trainer-audio.js`, `app/tts-worker.js`), без отправки текста TTS-сервису. При задержке — системный голос; при паузе/остановке worker завершается. Лицензии и источники: docs/THIRD_PARTY.md.
- Характер тренера («Строгий», «Весёлый», «Спокойный») меняет тон и голос, но не факты и не правила безопасности.
- По явному выбору пользователя 25 октября голосовые вопросы распознаёт сервис браузера (`SpeechRecognition` / `webkitSpeechRecognition`): аудио может уходить этому сервису. Перед кнопкой микрофона показано пояснение; приложение не сохраняет аудио, микрофон выключается при паузе, остановке и уходе. Видео не отправляется. Для ответа локальная LLM получает текст вопроса и проверенную сводку без кадров; без неё отвечает модуль правил.
- Кнопки скачивания Qwen отделены от переключателя использования. Статус «Скачана» определяется `hasModelInCache`, а не флагом localStorage. Загрузка отменяется перед стартом эфира, незавершённые workers освобождаются.

## Команда
Два человека ведут агентов и принимают решения; роли людей зафиксированы в docs/AI_STRATEGY.md.

| Агент | Владеет | Не трогает |
|---|---|---|

| vision | coach-engine.js, coach-motion.js, coach-policy.js, skills/*, rhythm.js, engine.test.mjs, motion.test.mjs, policy.test.mjs, skills.test.mjs, rhythm.test.mjs: поза, мяч, проверка движений, уроки, бюджет сообщений, банк фраз, ритм, тесты | интерфейс, app/ |
| coach-llm | coach-llm.js, llm-worker.js, coach-planner.js, coach-talk.js, llm.test.mjs, planner.test.mjs, talk.test.mjs: WebLLM, промпт тренера, подбор навыков, разговор в чате, проверка ответов | зрение, интерфейс |
| qa | docs/TEST_PLAN.md, docs/AI_STRATEGY.md: приёмка, проверка на телефонах, журнал дефектов с цифрами | исходники без согласования с root |
| feature_developer | docs/FEATURE_ROADMAP.md, новые модули функций и их тесты по контракту root | существующие файлы других ролей без назначения; сборка и публикация |
| root | app/main.js, app/live.js, app/store.js, app/viewport.js, app/voice-queue.js, sw.js, store.test.mjs, viewport.test.mjs, voice-queue.test.mjs, scripts/, .github/workflows/: интеграция, камера, клавиатура, очередь голоса, данные на устройстве, работа без сети, сборка, публикация на GitHub Pages, финальная проверка | — |

Общие контракты (формат результата анализа, события уроков, сводка для LLM) root сообщает агентам до реализации.

Агент развития сохранён в `.codex/agents/feature_developer.toml`. Пример поручения:
«Подключи feature_developer: выбери следующую задачу из docs/FEATURE_ROADMAP.md,
обоснуй пользу и критерий жюри, согласуй контракт с root и реализуй одну функцию с проверками».
Агент запускается по поручению; это не фоновый процесс и не расписание.

## MCP и Context7
- В корне лежит `.mcp.json` с сервером Context7 (`https://mcp.context7.com/mcp`, транспорт HTTP). Claude Code подхватывает его при открытии проекта и спрашивает разрешение на проектные MCP-серверы один раз.
- Инструменты: `resolve-library-id` (найти библиотеку: `libraryName`, `query`) и `query-docs` (получить документацию: `libraryId`, `query`, `language`).
- Проверенные идентификаторы: MediaPipe `/google-ai-edge/mediapipe` (сайт документации `/websites/developers_google_edge_mediapipe`), WebLLM `/mlc-ai/web-llm`.
- Правило: перед использованием любого API MediaPipe или WebLLM агент вызывает `query-docs` с конкретным вопросом и опирается на ответ, а не на память. Выдержку с датой записывать в docs/AI_STRATEGY.md.
- Ключ API не обязателен; для больших лимитов добавить заголовок `Authorization: Bearer <ключ>` в свою пользовательскую конфигурацию (`claude mcp add --transport http context7 https://mcp.context7.com/mcp --header "Authorization: Bearer <ключ>"`), в репозиторий ключ не класть.
- Чтобы инструменты Context7 не спрашивали подтверждение, в `.claude/settings.json` можно разрешить `mcp__context7__resolve-library-id` и `mcp__context7__query-docs`.

## Правила
- До изменений прочитать релевантные файлы; сохранять чужую работу.
- Не запускать сборки и публикацию параллельно. Публикация идёт автоматически с `main` через GitHub Pages; за workflow отвечает root.
- Актуальные API MediaPipe и WebLLM проверять через Context7 или исходники пакета; не выдумывать API.
- Камера включается после явного действия. Понятно обрабатывать отказ камеры, недоступность модели, отсутствие человека, невидимый мяч, отсутствие WebGPU.
- При остановке и уходе со страницы освобождать камеру, анимации, модели зрения и LLM (unload).
- Не хранить и не отправлять видеокадры. История сохраняется локально без видео. LLM кадров не видит.
- Касания мяча показывать только при реальной детекции мяча; иначе метрика называется «подъёмы стопы» с пояснением. Демо явно обозначать как симуляцию, в историю не писать.
- Не показывать фиктивную точность, зрителей, лайки или сгенерированные отзывы. LLM не придумывает числа, которых нет в сводке.
- Тренер не флудит: всё, кроме шагов урока, идёт через бюджет сообщений; замечание звучит, когда ошибка повторилась; голос не обрывает фразу, новая ждёт в очереди.
- Интерфейс эфира минимальный: карточка шага, счётчик, одна строка тренера, три кнопки; остальное — в меню.
- Анализ позы не ниже 8 кадров/с на телефоне; детектор мяча и LLM уступают приоритет позе.
- Логика навыков, уроков, мяча, банка фраз, сводки и проверки ответа LLM — чистые функции с тестами (`node --test`). Тестировать обычный ввод, отсутствие человека, отказ камеры, остановку, дрожание точек, ложные касания, выдуманные числа.
- Сначала функциональный основной сценарий (вход → чат → навык или маршрут → эфир → итог в чате), затем оформление.
- Вести docs/AI_STRATEGY.md с цифрами: тесты, итерации, дефекты, решения и причины. Документировать реальные команды запуска и известные ограничения.
- Для защиты держать запасное видео чеканки в docs/demo/ и заранее скачанную модель LLM на демо-телефоне.
