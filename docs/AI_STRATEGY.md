# AI Engineering Strategy — Aimo

Дата начала: 24 октября 2026 года. Этот журнал описывает разработку прототипа;
он не подтверждает его участие в хакатоне и не подменяет правила о заготовках.

## Задача пользователя

Вертикальная трансляция с телефона и контекстные комментарии тренера в реальном
времени. Первый целевой навык — чеканка мяча. Референс пользователя определяет
композицию live-видео и комментариев, а не личность человека в примере.

## Принятые решения

| Решение | Основание | Кто отвечает |
|---|---|---|
| Статическое браузерное приложение с ES modules | Быстрый запуск и HTTPS-тестирование с телефона без отдельного сервера приложения | root |
| MediaPipe Pose Landmarker в браузере | Реальная модель распознавания позы без API-ключа и загрузки кадров на сервер | vision |
| Комментарии по наблюдаемым ориентирам и правилам | Проверяемость подсказок; не выдавать текстовую генерацию за измерение техники | vision |
| Отдельная демонстрация с маркировкой | Позволяет проверить интерфейс без камеры и не смешивать симуляцию с наблюдением | root, frontend |
| Разделённое владение файлами | Избежать конфликтов при параллельной разработке | вся команда |

Эти строки отражают согласованную архитектуру. Они не означают, что все функции
уже реализованы или проверены.

## Ограничения, которые необходимо объяснить пользователю

- Ориентиры тела не дают точного числа касаний мяча. Счётчик движений нельзя
  подписывать как касания без отдельной надёжной модели мяча.
- Ракурс, освещение, видимость тела и устройство влияют на распознавание.
- Демо является симуляцией и не подтверждает качество реального анализа.
- Пока не проведены проверки на физических телефонах, нельзя заявлять полную
  совместимость со всеми мобильными браузерами.
- Голос зависит от доступных браузерных возможностей; текст остаётся основным каналом.

Видео и ключи не включать в журнал. Сохранять только необходимые сведения о проверках.

Дополнительная проверка DOM: все 30 литеральных ссылок `$(id)` в app.js найдены
среди 50 ID страницы. Динамические селекторы и браузерные состояния этим тестом не покрываются.

## 25 октября: нейро-тренер в эфире (версия для хакатона)

Критерии жюри: оригинальность 25%, польза 20%, работоспособность 20%, качество
исполнения 15%, работа в команде 10%, использование ИИ 10%. Полный промпт проекта:
docs/PROMPT.md. Решения ниже приняты командой из двух человек после уточняющих
вопросов агента.

| Решение | Основание | Критерий |
|---|---|---|
| Уроки с переходом по наблюдениям, лента эфира, характер тренера | Отличие от «счётчика повторов»: тренер ведёт, а не считает | Оригинальность |
| Каталог навыков из модулей данных в `skills/` | Новый навык — один файл; в каталоге только работающие навыки | Качество, польза |
| Детектор мяча MediaPipe Object Detector (sports ball) | Честные касания и падения вместо «движений ноги» | Работоспособность, польза |
| Живой тренер как маленькая LLM в браузере (WebLLM, Qwen2.5) вместо облачного API | Без сервера и ключей; кадры не покидают устройство; работает на сцене без сети после кеширования | Польза, работоспособность |
| LLM получает только числовую сводку, ответ проверяется кодом | Модель не может выдумать результат; при сбое — фраза по правилам | Честность, качество |
| Детектор мяча и LLM уступают приоритет позе | Поза не ниже 8 кадров/с на телефоне | Работоспособность |
| Запасное видео в docs/demo и заранее скачанная модель | Страховка защиты от света, сети и камеры | Работоспособность |

### 25 октября: чат подбора навыков

Запрос команды: человек хочет чему-то научиться, но не знает чему; ИИ понимает цель
и выстраивает навыки. Решение и его граница:

- Маршрут строится только из каталога. Модуль `coach-planner.js`: описание каталога
  для модели, промпт с требованием JSON `{plan, reply}`, проверка ответа (только
  существующие id, не больше 3, русский язык, без эмодзи, числа только из каталога),
  подбор по ключевым словам без модели, следующий навык по маршруту.
- Живой тренер получает ответ через новый метод `chat()` в coach-llm.js; непроверяемый
  ответ заменяется подбором по ключевым словам, и статус в интерфейсе говорит об этом.
- Граница по честности: модель не создаёт новые навыки. Навык здесь — правила по позе
  и мячу с тестами; сгенерированный текст урока без зрения означал бы «засчитывание»
  шагов, которых тренер не видел. Для цели вне каталога ответ: навыка пока нет,
  вот ближайшие.
- Найдено тестом и исправлено: проверка эмодзи в обоих валидаторах (планировщик и
  живой тренер) пропускала символы вне диапазона U+1F300–U+1FAFF, например ⚽;
  заменена на `\p{Extended_Pictographic}`. Склонения «3 шага» вместо «3 шагов».
- Автотестов 46 (10 новых), 0 падений. Headless Chrome 390×844: три подсказки-чипа,
  ввод с клавиатуры, карточка маршрута, бейджи в каталоге, сброс, сохранение в
  localStorage, демо и итог после этого; ошибок консоли нет. Ответ локальной модели
  на устройстве не проверялся (P03).

### 25 октября: MCP и Context7

- В репозиторий добавлен `.mcp.json` с сервером Context7 по HTTP
  (`https://mcp.context7.com/mcp`); при первом открытии проекта Claude Code просит
  подтвердить проектный сервер. Ключ API не обязателен, в репозитории его нет.
- Сервер проверен запросами по протоколу MCP: версия Context7 4.4.3, инструменты
  `resolve-library-id` и `query-docs`. Найденные идентификаторы: MediaPipe
  `/google-ai-edge/mediapipe`, WebLLM `/mlc-ai/web-llm`.
- Сверка через `query-docs`: схема Web Worker в WebLLM (WebWorkerMLCEngineHandler
  в воркере, `CreateWebWorkerMLCEngine(worker, modelId, { initProgressCallback })`,
  `engine.unload()`) совпадает с `llm-worker.js` и `coach-llm.js`. У MediaPipe
  подтверждены `createFromOptions`, `detectForVideo(frame, timestamp)` и режим
  `runningMode: 'VIDEO'`, который используется в `coach-engine.js`.
- Правило для агентов зафиксировано в AGENTS.md: API сверять через `query-docs`
  до использования и записывать выдержку с датой сюда.
- Проверка в новой сессии (25 октября): из папки проекта запущена отдельная
  неинтерактивная сессия Claude Code (`claude -p`, модель Sonnet) с просьбой
  воспользоваться Context7. Сервер подхвачен из `.mcp.json`, разрешения из
  `.claude/settings.json`: вызовы `resolve-library-id` («web-llm» →
  `/mlc-ai/web-llm`) и `query-docs` («MLCEngine unload» → «Unloads all loaded
  models and clears their associated configurations») прошли без запросов
  подтверждения, 3 хода, ошибок нет. Конфигурация работает у любого участника
  после `git pull`.

### 25 октября, поздний вечер: вкладка «Эфир» и явный выбор камеры

Запрос пользователя: кнопка «Эфир» внизу должна быть обычной вкладкой, внутри — выбор
навыка из списка и тренировка; на iPhone кнопки меню камеры путались: «Широкий угол 0.5×»
менял камеру, «Весь кадр без обрезки» делал наоборот.

Причина путаницы в коде: три переключателя-тумблера («Сменить камеру», «Широкий угол»,
«Весь кадр») описывали не состояние, а действие, и показывали то, что было запрошено, а не
то, что реально включилось. Широкий угол по умолчанию был включён, поэтому первая смена на
заднюю камеру сразу давала 0.5×, а тумблер «0.5×» выглядел как ещё одна смена камеры.
Решение: в меню два явных выбора — «Камера: Фронтальная / Задняя / Задняя 0.5×» и
«Масштаб: Весь кадр / На весь экран». Отмечается камера, которую сообщает сама
видеодорожка (`getSettings().facingMode` и `deviceId`), а не настройка. Повторный выбор
текущей камеры ничего не перезапускает; если 0.5× недоступен, тренер честно пишет об этом
и остаётся обычная задняя. Вкладка «Эфир» стала обычной: список восьми навыков по
разделам, выбор запоминается, кнопка «Начать эфир: …» называет навык, рядом демо и видео.

Попутно найден и исправлен дефект стилей: при удалении ряда кружков блок стилей от
«Атомов» до чата продублировался (113 лишних строк). Меню эфира для аудита доступности
стало группой переключателей вместо `role="menu"`.

Проверки: 180 тестов, 0 падений; headless Chrome: вкладка «Эфир» (8 строк, выбор,
подпись кнопки), меню камеры с тестовой камерой (выбор, повторный выбор без перезапуска,
